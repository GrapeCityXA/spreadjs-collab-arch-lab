多机负载（controller + agent）

controller 跑编排器 / LB / Redis / 控制台；其它机器只跑 npm run agent。 控制台只负责把 agent 挂到 LB 并驱动负载，不会在别的机器上启动任何进程。

本机
在另一台机器上启动 agent：
npm run agent -- --port=9100 \
  --lb=http://<controller-ip>:3000 \
  --token=<SJS_LB_ADMIN_TOKEN> \
  --public-host=<这台机器的 IP>
然后在这里填入 http://<这台机器>:9100，加入后下一次“启动架构”会带着它一起 POST /api/stack/up { agents:[…] }。agent 进程本身必须先手动启动好，console 不会替你启动。

3协作客户端

在浏览器里打开真实的 SpreadJS 协作客户端。同一房间的两个客户端会实时同步；落在不同节点时，能否同步正是架构的差别。

提示：把客户端 A 固定在 node-8081、客户端 B 固定在另一个节点，然后编辑同一个单元格—— 在 分区多机（无 Redis 适配器） 下，B 永远收不到；切到 共享 room 多机 就通了。

4架构体检

检查针对当前运行的技术栈执行：同节点实时性、跨节点实时性、加入一致性、存储一致性、房间隔离、ACK 延迟、以及「最终一致掩盖断链」陷阱。
